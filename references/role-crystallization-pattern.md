# Role Crystallization Pattern

Use this when a master baton has already narrowed the work to an unresolved role / boundary question and the next session should not jump into implementation.

## Recommended sequence

1. Read the master baton first.
2. Read any synthesis artifact the master baton points at (for example a portable-vs-context-specific matrix).
3. Read the relevant source docs.
4. Use docs-driven grilling to sharpen the unresolved boundary question one step at a time.
5. Stop as soon as one boundary becomes defendable in plain language.

## Good fit signals

- The work is known to be important, but the role is still fuzzy.
- The session needs synthesis before setup.
- The operator explicitly says the answer is not yet known.
- There is a macro baton already in place and a narrower baton needs to point at it.

## Pitfall

Do not let the narrower baton quietly become a setup plan. If the role is still ambiguous, the baton should stay in definition mode and keep the next session on the smallest possible boundary question.
